Todo list.  Open items only - finished work is written up in the commit
messages that made the changes, not kept here.

- the console work still needs running on a mac and on windows. everything
that can be checked without them now is: the POSIX half is verified by driving
a BDOS 6 hex-echo loop through a linux pty, which gives 12 for Ctrl+R, 16 for
Ctrl+V and 0F for Ctrl+O, and tests/run_tests.sh cross-compiles the windows
build so a change that breaks only that half cannot go unnoticed.

what is left needs the hardware. a linux pty cannot prove the thing the IEXTEN
clear was for, because BSD/XNU gates VLNEXT and VDISCARD on IEXTEN outside the
ICANON block, so ^V and ^O want a real mac. windows needs a real console for
the arrow keys, for Insert (expect 16) and for the ctrl+arrow pairs: the
extended-key path sits behind is_terminal(), so redirected stdin never reaches
the diamond table at all, and no cross-compile exercises _getch. wine is not a
substitute - its console layer does not reproduce _getch/_kbhit faithfully
enough for a pass to mean anything. any harness has to be a pty and not a
pipe, because stdin_has_data() returns false for a non-tty by design and BDOS
6 therefore never sees anything over a pipe on POSIX.
