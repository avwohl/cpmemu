Todo list.  Open items only - finished work is written up in the commit
messages that made the changes, not kept here.

- the console work still needs a hand test on a mac and on windows. the POSIX
half is done: driving a BDOS 6 hex-echo loop through a linux pty gives 12 for
Ctrl+R, 16 for Ctrl+V and 0F for Ctrl+O. what a linux pty cannot prove is the
thing the IEXTEN clear was actually for, because BSD/XNU gates VLNEXT and
VDISCARD on IEXTEN outside the ICANON block - so ^V and ^O want a real mac.
windows needs a real console for the arrow keys and for Insert (expect 16):
the extended-key path sits behind is_terminal(), so redirected stdin never
reaches the diamond table at all. any harness has to be a pty and not a pipe,
because stdin_has_data() returns false for a non-tty by design and BDOS 6
therefore never sees anything over a pipe on POSIX.

- the windows half of the read(2) fix has never been compiled. there is no
mingw cross-compiler on the development box, so console_getchar()'s
_read(_fileno(stdin), ...) branch in src/os/windows/platform.cc was reviewed
but not built. it uses only calls the same file already makes elsewhere, and
init() has already put stdin in _O_BINARY so it reads the same bytes getchar()
did, but the next windows build is its first real compile.

- BDOS 1 turns an EOF into CR, so a program looping on BDOS 1 over an
exhausted stdin spins forever emitting carriage returns instead of ever
finishing. long-standing, and unchanged by the read(2) work. it also means any
piped BDOS 1 test needs a sentinel byte such as ^Z to stop on. worth deciding
whether repeated EOF should instead terminate the program.

- the option loop stops at the first argument that does not start with '-',
treating it as the program name, so a flag written after the program or config
file is silently ignored. `cpmemu prog.cfg --no-ctrl-c-exit` does not turn the
^C exit off and says nothing about it. the flags do outrank the config file
when they are parsed at all; this is about them not being parsed.

- ctrl+up and ctrl+down are not in the windows extended-key table, so they miss
the lookup, come back as a synthesized 0, and are swallowed - the user sees
nothing. ctrl+left and ctrl+right are mapped, to ^A and ^F. README.md documents
only the two that exist, so the docs are honest, but the pair is a gap worth
filling if a WordStar user asks for it.

- there is no issue tracker or TODO convention in this repo (docs/archive holds
stale narrative notes, and README.md has no Contributing section), which is why
this file exists. github issues on avwohl/cpmemu is the only other mechanism
available.
