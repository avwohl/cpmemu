Todo list.  Open items only.

[ANY] A / in a command-line word becomes _ in the default FCB.
  2.2's CCP takes / as a name character, and DRI's STAT reads its
  attribute from the second FCB: STAT T.TXT $R/O answers "Invalid File
  Indicator" here because FCB 2 holds $R_O.  filename_to_fcb replaces any
  character is_valid_cpm_char refuses; a / that does not start the word
  (./ and / are host paths) should be kept, as the CCP keeps it.  Older
  than this branch; found by its verifier.

[ANY] A make of a name the command line gave as a host path lands in the
  drive's directory, not at that path.
  cpmemu fcb_io.com ./sub/t.txt 'MHAJ1K2U3WCZ0OL' makes t.txt in the working
  directory and then opens sub/t.txt, the file_map entry, and prints its old
  text; ED on ./sub/x.txt renames sub/x.txt to sub/x.bak and leaves the
  edited x.txt in the working directory.  bdos_make_file and the rename's
  new path never look in file_map.  Older than this branch.  Missing: which
  of file_map's spellings a make should honour - a path given on the command
  line, but not a name a rename planted there.
